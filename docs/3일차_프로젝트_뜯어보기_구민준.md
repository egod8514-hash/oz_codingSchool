## 0. 전체 구조 한눈에 보기

> ⚠️ README의 트리 그림에는 `static/`, `media/`, `templates/`가 `app/` 안에 있지만, 커밋 이력("static, media 디렉터리 루트 디렉터리 하위로 이동")과 실제 폴더를 보면 **프로젝트 루트로 이동된 상태**입니다. 아래는 실제 기준입니다.

```
AH_health_web_development_assignment
├── README.md
├── .env.example              # 환경변수 예시 → 복사해서 .env 생성
├── .gitignore
├── alembic/                  # Alembic 마이그레이션 (이미 초기화되어 있음)
│   ├── env.py                # 비동기 마이그레이션 실행 설정
│   ├── script.py.mako        # 마이그레이션 파일 생성 템플릿
│   └── versions/             # 생성된 마이그레이션 파일이 쌓이는 곳
├── alembic.ini
├── app/
│   ├── core/
│   │   ├── config.py         # .env → 설정 객체
│   │   └── db/
│   │       ├── databases.py  # 엔진·세션·Base·세션 의존성
│   │       └── models.py     # 공통 Mixin (UUID / Timestamp / SoftDelete)
│   ├── apis/                 # 라우터(엔드포인트)
│   ├── models/               # 테이블 모델
│   ├── repositories/         # DB 접근(CRUD)
│   ├── schemas/              # 요청/응답 검증(Pydantic)
│   ├── services/             # 비즈니스 로직
│   ├── main.py               # 앱 진입점
│   └── Dockerfile            # 현재 빈 파일
├── static/                   # 프론트엔드 파일 (index.html, JS, CSS)
│   ├── index.html
│   ├── app.js / apis.js / pages.js / utils.js
│   ├── styles.css
│   └── templates/
├── media/                    # 사용자 업로드 파일 (없으면 서버 시작 시 자동 생성)
├── docker-compose.yml        # FastAPI + MySQL 컨테이너
├── docs/                     # 문서
├── daily/                    # worklog
├── pyproject.toml
└── uv.lock
```

요청 흐름:

```
Client → apis(라우터) → services(비즈니스 로직) → repositories(DB 접근) → models(테이블)
                ↑ schemas(요청/응답 데이터 검증)
```

## 1. 디렉터리별 역할과 작성할 파일 내용

### `app/core/`
앱 전체에서 공통으로 쓰는 **설정과 인프라 코드**.
- `config.py` : 환경변수(.env) → 설정 객체
- `db/databases.py` : DB 엔진, 세션, `Base`, 세션 의존성 함수
- `db/models.py` : 모든 모델이 공통으로 가져다 쓰는 **Mixin 클래스**(UUID, 생성/수정 시간, 소프트 삭제)
- 앞으로 추가할 것: 보안(JWT, 비밀번호 해시), 공통 예외 처리, 로깅 등

### `app/models/`
**DB 테이블과 1:1로 매핑되는 SQLAlchemy ORM 모델**.
- **작성할 내용**: `Base`와 Mixin을 상속한 클래스, 컬럼, 테이블 간 관계(`relationship`, `ForeignKey`)
- ⚠️ `alembic/env.py`가 `from app import models`로 불러오므로, **`app/models/__init__.py`에서 각 모델을 import**해야 autogenerate가 인식함

### `app/repositories/`
**DB에 직접 접근하는 계층**. 쿼리만 담당.
- **작성할 내용**: `get_by_id`, `create`, `update`, `delete`, 목록 조회 등 (비동기 `AsyncSession` 사용)
- 비즈니스 규칙은 넣지 않음

### `app/schemas/`
**Pydantic 모델**. API 요청/응답 데이터의 구조와 검증.
- **작성할 내용**: `UserCreate`, `UserUpdate`, `UserResponse`처럼 용도별 스키마
- ORM 모델을 그대로 노출하지 않고 스키마로 변환해 응답(비밀번호 등 민감 필드 제외)
- 응답 스키마에는 `model_config = ConfigDict(from_attributes=True)`

### `app/services/`
**비즈니스 로직 계층**.
- **작성할 내용**: 중복 체크, 권한 검증, 여러 repository 조합, 도메인 예외 발생
- 라우터는 얇게, 로직은 서비스에

### `app/apis/`
**HTTP 엔드포인트(라우터) 계층**.
- **작성할 내용**: `APIRouter`, 경로/메서드, `Depends(async_get_db)`, 상태 코드, `response_model`
- 만든 라우터는 `main.py`에서 `app.include_router(...)`로 등록
- `main.py`의 catch-all이 `api/v1`로 시작하는 경로를 API로 간주하므로, **API 경로는 `/api/v1/...` 형태**로 만드는 것이 전제

### `static/` (프로젝트 루트)
**프론트엔드 파일을 두는 곳**. 서버가 가공 없이 그대로 내려주며 `/static` 경로로 접근.

| 파일 | 역할(파일명과 커밋 메시지 기준) |
|---|---|
| `index.html` | 앱의 유일한 진입 HTML. `/` 요청 시 이 파일을 반환 |
| `app.js` | 앱 초기화, 로그인 상태/토큰 처리 등 전체 흐름 |
| `apis.js` | 백엔드 API를 호출하는 함수 모음 |
| `pages.js` | 화면(페이지) 렌더링 |
| `utils.js` | 공통 유틸 함수 |
| `styles.css` | 스타일 |
| `templates/` | 화면용 HTML 조각 등 |

- 커밋 이력(회원가입 핸들러, 로그아웃 API, 토큰 리프레시, 해시 이동 차단)을 보면 **회원가입/로그인/로그아웃/토큰 갱신 API를 백엔드가 제공하는 것을 전제**로 한 프론트입니다.
- 💡 **`static/apis.js`를 열어보면 프론트가 호출하는 API 경로와 요청 형식**을 알 수 있어, 백엔드 API를 설계할 때 기준이 됩니다.

### `media/` (프로젝트 루트)
**사용자가 업로드하는 가변 파일** 저장 공간. `/media` 경로로 서빙.
- static은 "개발자가 넣은 고정 파일", media는 "사용자가 올린 파일"
- 비어 있는 폴더는 git에 올라가지 않기 때문에, `main.py`가 **없으면 자동으로 생성**하도록 되어 있음

### `alembic/`
**DB 스키마 변경 이력 관리**. 이미 초기화되어 있어서 `alembic init`은 다시 하지 않음.

## 2. 각 파일의 역할

### `app/main.py`
애플리케이션 **진입점**.

| 코드 | 역할 |
|---|---|
| `app = FastAPI()` | 앱 인스턴스 생성 |
| `app.include_router(...)` | `apis/`에서 만든 라우터를 등록하는 자리 |
| `BASE_DIR = Path(__file__).resolve().parent.parent` | 경로 기준점. `app/main.py`의 부모의 부모 = **프로젝트 루트** |
| `os.mkdir(...)` | 루트의 `static/`, `media/`가 없으면 자동 생성 |
| `app.mount("/static", ...)`, `app.mount("/media", ...)` | 폴더를 URL 경로로 서빙(프론트 파일, 업로드 파일) |

그리고 3개의 엔드포인트:

- `GET /healthcheck` → `{"status": "ok"}`. docker-compose의 healthcheck가 이 경로를 호출. Swagger 문서에는 숨김(`include_in_schema=False`)
- `GET /` → `static/index.html` 반환
- `GET /{path:path}` (**catch-all**) → 위에서 매칭되지 않은 모든 GET 요청에 `index.html`을 반환. 단, `api/v1`, `static/`, `media/`로 시작하면 404

**catch-all의 의도**: 프론트엔드가 브라우저에서 화면 전환을 처리하는 **SPA(Single Page Application) 방식**을 지원하기 위한 것. 서버가 HTML을 조립(Jinja2)하지 않고, `index.html` 하나를 내려준 뒤 JS(`app.js`, `pages.js`)가 화면을 그립니다.

> 💡 FastAPI 기본 문서 경로(`/docs`)는 앱 생성 시 먼저 등록되므로 catch-all보다 우선 매칭됩니다.
> 💡 라우트 매칭은 **등록 순서**대로라서, 새 라우터는 catch-all 정의보다 **위쪽**(`include_router` 자리)에서 등록해야 합니다.

### `app/core/config.py`
**`.env`를 읽어 설정 객체를 만드는 파일**. `pydantic-settings`의 `BaseSettings` 사용.

```python
class Settings(BaseSettings):
    DB_USER: str = "root"
    DB_PASSWORD: str = "password1234"
    DB_HOST: str = "localhost"
    DB_PORT: str = "3306"
    DB_NAME: str = "ai_health"

    model_config = {"env_file": ".env", "extra": "ignore"}
```

- 환경변수/`.env`에 값이 있으면 그 값을, **없으면 위의 기본값**을 사용
- `env_file: ".env"`는 **실행하는 위치(현재 디렉터리)** 기준 → 프로젝트 루트에서 실행해야 `.env`를 찾음
- `extra: "ignore"` → `.env`에 정의 안 된 키(예: `DB_ROOT_PASSWORD`)가 있어도 에러 없이 무시
- 이 값들이 `databases.py`에서 DB 접속 URL을 조립하는 데 쓰임

### `pyproject.toml`
**프로젝트 메타데이터와 의존성 선언**. Python 버전, 의존성(fastapi, sqlalchemy, alembic, asyncmy, uuid6, pydantic-settings 등)이 들어감. 패키지 추가는 `uv add <패키지>`.

### `uv.lock`
**의존성 잠금 파일**. 하위 의존성까지 정확한 버전/해시를 고정해 팀원 모두 같은 환경을 재현. 직접 수정하지 않고 **반드시 커밋**. 설치는 `uv sync`.

### `alembic.ini`
Alembic **설정 파일**(스크립트 위치, 로깅 등). DB URL은 여기 있는 값 대신 `env.py`가 앱의 `DATABASE_URL`로 **덮어씀**.

### `alembic/env.py`
**마이그레이션 실행의 핵심 파일**.
- `sys.path.append(os.getcwd())` : 프로젝트 루트에서 실행해야 `app` 모듈을 import 가능
- `from app.core.db.databases import Base, DATABASE_URL` : Base와 접속 URL 가져옴
- `from app import models` : 모델을 로드해야 테이블 변경을 감지
- `config.set_main_option("sqlalchemy.url", DATABASE_URL)` : ini의 URL 덮어쓰기
- `target_metadata = Base.metadata` : 이 메타데이터와 실제 DB를 비교해 변경점 생성
- **비동기 엔진**(`async_engine_from_config`)을 쓰므로 `asyncio.run(run_migrations_online())` 구조

### `alembic/script.py.mako`
마이그레이션 파일을 만들 때 쓰는 **템플릿**. 보통 수정하지 않음.

### `alembic/versions/`
`alembic revision`으로 생성된 **마이그레이션 파일** 저장소. 커밋해서 팀원과 공유.

### `docker-compose.yml`
**FastAPI + MySQL을 한 번에 실행**하는 설정.

| 서비스 | 설명 |
|---|---|
| `fastapi` | `app/Dockerfile`로 빌드, `uvicorn --reload`로 실행, 포트 8000, `/healthcheck`로 상태 확인 |
| `mysql` | `mysql:8.0` 이미지, 데이터는 `mysql_volume`에 영속화, 접속 정보는 `.env` 값을 사용 |

- `mysql`의 포트 매핑은 `"${DB_PORT}:3306"` → **내 PC에서는 `DB_PORT`, 컨테이너 내부에서는 3306**
- ⚠️ **현재 `app/Dockerfile`이 빈 파일**이라 `fastapi` 서비스는 빌드할 수 없음. 그래서 지금은 **`mysql`만 compose로 띄우고, FastAPI는 로컬에서 `uv run`으로 실행**하는 방식으로 사용

### `app/Dockerfile`
FastAPI 앱 이미지를 빌드하는 파일. **현재는 완전히 빈 파일**이라 앞으로 채워야 하는 부분(베이스 이미지, uv 설치, 의존성 설치, 코드 복사 등). 이번 단계 과제 범위인지는 팀에서 확인.

### `.env.example` / `.env`
`.env.example`은 **환경변수 예시 파일**이고, `.env`는 **직접 만들어야 하는 실제 설정 파일**(git에 올리지 않음).

```bash
cp .env.example .env     # 복사 후 값을 환경에 맞게 수정
```

```env
# 키 이름은 docker-compose.yml(${DB_...})과 config.py가 같이 쓰므로 바꾸면 안 됨
DB_ROOT_PASSWORD=...
DB_NAME=...
DB_USER=...
DB_PASSWORD=...
DB_HOST=localhost
DB_PORT=3306
```

> `DB_USER=root`는 사용 불가: MySQL 공식 이미지는 `MYSQL_USER`에 root를 지정하면 시작 에러가 남. 일반 사용자 이름을 사용

## 3. 데이터베이스 연결 설정 — `app/core/db/databases.py`

```python
DATABASE_PREFIX = "mysql+asyncmy://"
DATABASE_URI = f"{settings.DB_USER}:{settings.DB_PASSWORD}@{settings.DB_HOST}:{settings.DB_PORT}/{settings.DB_NAME}"
DATABASE_URL = f"{DATABASE_PREFIX}{DATABASE_URI}"

async_engine = create_async_engine(DATABASE_URL, echo=False, future=True)
AsyncSessionLocal = async_sessionmaker(bind=async_engine, autoflush=False, expire_on_commit=False)
Base = declarative_base()

async def async_get_db() -> AsyncGenerator[AsyncSession, None]:
    async with AsyncSessionLocal() as db:
        yield db
```

| 코드 | 역할 |
|---|---|
| `mysql+asyncmy://` | **MySQL + 비동기 드라이버(asyncmy)** 사용 |
| `DATABASE_URL` | `config.py`의 `settings` 값으로 접속 문자열을 조립 |
| `create_async_engine` | DB 연결 풀을 관리하는 **비동기 엔진** (`echo=True`로 바꾸면 SQL 로그 출력) |
| `async_sessionmaker` | 요청마다 `AsyncSession`을 만드는 팩토리. `expire_on_commit=False`라 commit 후에도 객체 속성 접근 가능 |
| `Base` | **모든 모델이 상속할 베이스**. `Base.metadata`를 Alembic이 사용 |
| `async_get_db` | FastAPI **의존성 함수**. 요청 시작 시 세션을 열고, 끝나면 자동으로 닫음 |

사용법:

```python
@router.get("/api/v1/users")
async def list_users(db: AsyncSession = Depends(async_get_db)):
    ...
```

### 공통 Mixin — `app/core/db/models.py`

모델에 **조합해서 쓰는 공통 컬럼 묶음**.

| Mixin | 추가되는 컬럼 | 설명 |
|---|---|---|
| `UUIDMixin` | `uuid` (CHAR(36), PK) | UUIDv7을 기본키로 사용 (시간 순 정렬 가능) |
| `TimestampMixin` | `created_at`, `updated_at` | 생성/수정 시각 |
| `SoftDeleteMixin` | `deleted_at`, `is_deleted` | 실제 삭제 대신 **삭제 표시만** 하는 소프트 삭제 |

## 4. SQLAlchemy 모델 작성 + Alembic 마이그레이션

### 4-1. 모델 작성 (`app/models/user.py` 예시)

```python
from sqlalchemy import String
from sqlalchemy.orm import Mapped, mapped_column

from app.core.db.databases import Base
from app.core.db.models import UUIDMixin, TimestampMixin, SoftDeleteMixin


class User(UUIDMixin, TimestampMixin, SoftDeleteMixin, Base):
    __tablename__ = "users"

    email: Mapped[str] = mapped_column(String(255), unique=True, index=True)
    name: Mapped[str] = mapped_column(String(50))
```

`app/models/__init__.py`에 등록 (이게 없으면 마이그레이션에서 테이블이 감지되지 않음):

```python
from app.models.user import User  # noqa: F401
```

### 4-2. 마이그레이션 수행 흐름

**프로젝트 루트(`alembic.ini`가 있는 곳)에서 실행**, 그리고 **MySQL이 먼저 떠 있어야 함**.

| 단계 | 명령어 | 설명 |
|---|---|---|
| 0 | `docker compose up -d mysql` | DB 컨테이너 실행 |
| 1 | 모델 작성 + `models/__init__.py`에 import | `app/models/` |
| 2 | `uv run alembic revision --autogenerate -m "create users table"` | 모델과 DB를 비교해 마이그레이션 파일 생성 |
| 3 | 생성된 파일 검토 | `alembic/versions/`의 `upgrade()` / `downgrade()` 확인 |
| 4 | `uv run alembic upgrade head` | 최신 버전까지 DB에 적용 |
| 5 | `uv run alembic downgrade -1` | 필요 시 한 단계 롤백 |

기타: `alembic current`(현재 리비전), `alembic history`(이력)

> 💡 로컬에서 alembic을 실행할 때는 `.env`의 `DB_HOST=localhost`, `DB_PORT`는 compose에서 열어 둔 포트와 일치해야 함
> 💡 `versions/` 파일도 코드이므로 커밋. 팀원은 pull 후 `alembic upgrade head`만 하면 같은 스키마가 됨

## 5. API 구현 흐름

새 기능(예: 유저 생성 API)을 만들 때의 순서. **모든 DB 호출은 비동기(`async/await`)**.

1. **Model** — `app/models/`에 테이블 정의 (+ `__init__.py` 등록)
2. **Migration** — `alembic revision --autogenerate` → `alembic upgrade head`
3. **Schema** — `app/schemas/`에 요청/응답 스키마
4. **Repository** — `app/repositories/`에 CRUD
5. **Service** — `app/services/`에 비즈니스 로직
6. **API** — `app/apis/`에 라우터 작성 (경로는 `/api/v1/...`) 후 `main.py`에서 `include_router`로 등록
7. **프론트 연결** — `static/apis.js`가 호출하는 경로·형식과 맞는지 확인
8. **테스트** — `http://localhost:8000/docs` (Swagger UI)

### 요청 처리 예시 (`POST /api/v1/users`)

```
1. Client가 JSON 전송
2. apis: 라우터가 요청 수신, schemas.UserCreate로 자동 검증
3. apis → services: 검증된 데이터를 서비스로 전달
4. services: 이메일 중복 확인(repository 호출) → 중복이면 예외
5. services → repositories: 저장 요청
6. repositories: AsyncSession으로 INSERT, commit
7. 결과 User 모델 → schemas.UserResponse로 변환
8. Client에 JSON 응답
```

```python
# apis/user_apis.py
router = APIRouter(prefix="/api/v1/users", tags=["users"])

@router.post("", response_model=UserResponse, status_code=201)
async def create_user(body: UserCreate, db: AsyncSession = Depends(async_get_db)):
    return await user_service.create_user(db, body)

# main.py
app.include_router(user_router)     # catch-all 정의보다 위에 등록

# services/user.py
async def create_user(db: AsyncSession, body: UserCreate) -> User:
    if await user_repository.get_by_email(db, body.email):
        raise HTTPException(status_code=409, detail="이미 존재하는 이메일입니다.")
    return await user_repository.create(db, body)

# repositories/user.py
async def get_by_email(db: AsyncSession, email: str) -> User | None:
    result = await db.execute(
        select(User).where(User.email == email, User.is_deleted.is_(False))
    )
    return result.scalar_one_or_none()

async def create(db: AsyncSession, body: UserCreate) -> User:
    user = User(**body.model_dump())
    db.add(user)
    await db.commit()
    await db.refresh(user)
    return user
```

> 소프트 삭제를 쓰므로 조회 쿼리에서 `is_deleted` 조건을 **직접 걸어야 함** (자동으로 걸러지지 않음)
> API 경로를 `/api/v1`로 시작하지 않으면, 잘못된 GET 요청이 404 대신 `index.html`을 반환할 수 있음

## 7. 코드를 보며 발견한 주의점

팀원들과 논의해볼 만한 부분입니다.

1. **README의 구조도가 실제와 다름**
   README 트리에는 `static/`, `media/`, `templates/`가 `app/` 안에 있지만, 실제로는 **루트로 이동**된 상태입니다. `main.py`의 `BASE_DIR`(프로젝트 루트 기준)도 이에 맞춰져 있어 코드는 일관됩니다. 구조도만 갱신되지 않은 것으로 보입니다.

2. **`app/Dockerfile`이 비어 있음**
   빈 Dockerfile로는 `docker compose up`에서 `fastapi` 서비스를 빌드할 수 없습니다. 이후 Dockerfile을 작성할 때 아래를 함께 고려해야 합니다.
   - 컨테이너 안에서는 `DB_HOST=mysql`, `DB_PORT=3306`이어야 함 (기본값 `localhost`로는 MySQL에 접속 불가)
   - compose의 `fastapi` 서비스에 `env_file: .env` 같은 환경변수 전달 설정이 없음
   - `BASE_DIR`이 프로젝트 루트 기준이므로 `static/`, `media/`가 컨테이너 안에서 어디에 놓이는지 맞춰야 함

3. **컨테이너 내부 DB 포트**
   compose는 `"${DB_PORT}:3306"`으로 포트를 연결합니다. 컨테이너끼리 통신할 때는 호스트가 `mysql`(서비스 이름), 포트가 **항상 3306**입니다. `DB_PORT`를 3307 등으로 바꿨다면 컨테이너 안에서는 `DB_PORT` 값을 쓰면 접속이 안 됩니다.

4. **`TimestampMixin`의 시간 기본값 문제**
   `default=datetime.now(UTC)`는 함수를 호출한 결과값이라 **서버가 시작될 때 한 번만 계산**됩니다. 그래서 이후 생성되는 모든 행의 `created_at`이 같은 값이 될 수 있습니다. `onupdate`도 마찬가지입니다.
   → `default=lambda: datetime.now(UTC)` 처럼 **함수 자체를 넘기는 방식**으로 수정 필요 (또는 `server_default`만 사용).

5. **UUID와 `CHAR(36)` 타입 불일치 가능성**
   `default=uuid7`은 `UUID` 객체를 만드는데, 컬럼 타입은 `CHAR(36)`(문자열)입니다. 드라이버에 따라 INSERT 시 에러가 날 수 있어요. 에러가 나면 `default=lambda: str(uuid7())`로 문자열 변환하거나 `Uuid` 타입 사용을 검토.

6. **MySQL 준비 전에 앱이 먼저 뜰 수 있음**
   `depends_on: - mysql`은 컨테이너 시작 순서만 보장하고 **DB가 준비될 때까지 기다리지는 않습니다.** `condition: service_healthy`를 쓰면 mysql healthcheck 통과 후 앱이 시작됩니다.

7. **Alembic은 로컬에서 실행하는 구조**
   compose가 마운트하는 것은 `./app`뿐이라 `alembic/`, `alembic.ini`는 컨테이너에 없습니다. 마이그레이션은 로컬에서 `uv run alembic ...`로 실행하는 것을 기준으로 합니다.

8. **사소한 부분**
   - `config.py`에 DB 비밀번호 **기본값이 코드에 하드코딩**되어 있습니다. 과제용이라 괜찮지만 실제 서비스에서는 기본값 없이 `.env`로만 받는 편이 안전합니다.
   - `declarative_base`는 `sqlalchemy.orm`에서 import하는 것이 SQLAlchemy 2.0 권장 방식입니다.
   - `MYSQL_PORT` 환경변수는 mysql 공식 이미지에서 사용하지 않는 값입니다.
   - `catch_all` 안의 `from fastapi import HTTPException`은 파일 상단 import로 옮기는 것이 깔끔합니다.
