# 3일차 프로젝트 뜯어보기

## 1. 주요 디렉터리의 역할

### app/core/

여러 기능에서 공통으로 사용하는 프로젝트의 핵심 설정이나 공통 기능을 모아두는 곳

    - `config.py`: 프로젝트의 환경 설정을 관리
    - `constants.py`: 여러 기능에서 공통으로 사용할 상수 값을 관리
    - `message.py`: 공통으로 사용하는 메시지를 관리
    - `validation.py`: 여러 API에서 사용할 수 있는 공통 검증 로직을 관리
    - `db/`: 데이터베이스 연결 및 데이터베이스 관련 설정을 관리

공통 기능을 'core'에 분리하면 각 API에서 같은 코드를 반복해서 작성하는 것을 줄이고 유지보수를 쉽게 할 수 있음

### app/models/

데이터베이스의 테이블을 python 코드로 표현하는 곳

SQLAlchemy를 사용하여 테이블의 이름과 컬럼, 데이터 타입 등의 구조를 정의

예를 들어 회원 정보를 데이터베이스에 저장하면 `User` 모델을 만들어 회원 테이블의 `id`, `name`, `age`, `email` 등의 컬럼을 정의할 수 있음

### app/repositories/

데이터베이스에 실제로 데이터를 조회,추가,수정,삭제 하는 코드를 모아두는 곳

Service에서 필요한 데이터를 요청하면 Repository가 SQLAlchemy 등을 이용하여 실제 데이터베이스와 통신

예를 들어 회원 기능에서는 회원 전체 조회, 특정 회원 조회, 회원 추가, 회원 수정, 회원 삭제와 같은 데이터 베이스 처리 함수를 작성할 수 있음

### app/schemas/

API에서 주고받는 데이터가 어떤 형태여야 하는지 정의하는 곳

어떤 모양의 타입인지 정의하고 검증 

### app/services/

API에서 요청받은 기능을 실제로 처리하는 비즈니스 로직을 관리하는 곳

회원 조회나 회원 수정과 같은 실제 기능의 처리 로직을 담당

실제 처리 로직을 분리하게 되면 코드의 역할이 명확해지고 유지보수하기 쉬워짐

### app/apis/

클라이언트가 접근할 API 주소를 정의하고 요청을 받는 곳

GET, POST, PUT, DELETE 등의 HTTP Method와 URL을 정의하고, 요청받은 데이터를 필요한 Service 로직에 전달한 뒤 처리 결과를 클라이언트에게 응답하는 역할

현재 프로젝트에서는 `practice_apis.py`에서 `/practice_api`라는 공통 경로를 가진 Router를 생성하고 있으며, 회원 추가 및 삭제 API와 다른 Router들을 연결하고 있음

`get_user.py`와 `update_user.py`처럼 기능에 따라 API 파일을 분리하고 `include_router()`를 사용하여 하나의 Router에 연결할 수 있음

## 2. 주요 파일의 역할

### app/main.py

FastAPI 애플리케이션을 생성하고 실행에 필요한 기능들을 연결하는 프로젝트의 시작점

현재 프로젝트에서 FastAPI 어플리케이션을 생성하고, `practice_apis.py`에 작성된 API를 연결

`static`, `media` 폴더를 연결하여 CSS, JavaScript, 이미지 등의 파일을 사용할 수 있도록 하고, `\`경로로 접속하면 `index.html`을 보여줌

### app/core/config.py

프로젝트에서 사용할 설정값을 관리하는 파일

현재 프로젝트에서 데이터베이스에 접속하기 위한 사용자 이름, 비밀번호, 주소, 포트, 데이터베이스 이름 등의 설정을 관리

`.env` 파일에 작성된 환경변수를 불러와 설정ㅇ값으로 사용할 수 있도록 되어 있음

### pyproject.toml

Python 프로젝트의 기본 정보와 필요한 라이브러리를 관리하는 파일

프로젝트 이름과 버전, 사용할 python 버전이 설정되어 있고 FastAPI, SQLAlchemy, Alembic 등 프로젝트 실행에 필요한 라이브러리들이 `dependencies`에 작성되어 있음

### uv.lock

프로젝트에서 실제로 사용할 라이브러리들의 구체적인 버전을 기록하는 파일

`pyproject.toml`에 작성된 라이브러리를 기준으로 uv가 필요한 패키지와 버전을 계산하여 `uv.lock`에 기록

다른 컴퓨터나 팀원들의 개발 환경에서도 동일한 버전의 라이브러리를 설치하여 비슷한 실행 환경을 유지할 수 있음

## 3. 데이터베이스 연결 설정

### app/core/db/databases.py

데이터베이스에 연결하기 위한 설정을 관리하는 파일

`config.py`에서 DB 접속 정보를 가져와 실제로 MySQL과 연결할 준비를 하는 파일

## 4. SQLAlchemy 모델 작성과 Alembic 마이그레이션

SQLAlchemy는 Python에서 데이터베이스를 사용할 수 있도록 도와주는 라이브러리

SQLAlchemy의 모델을 사용하면 데이터베이스의 테이블 구조를 Python 클래스로 정의할 수 있음

1. SQLAlchemy를 사용하여 model을 작성
2. Alembic으로 모델의 변경 내용을 확인하여 마이그레이션 파일을 생성
3. 생성된 마이그레이션 파일을 확인
4. alembic upgrade head를 실행하여 변경 내용을 데이터베이스에 적용

SQLAlchemy는 데이터베이스 구조를 파이썬으로 정의하면 Alembic은 그 구조의 변경사항을 데이터베이스에 적용하고 관리하는것

## 5. API 구현 흐름

API는 클라이언트의 요청을 받은 후 여러 계층을 거쳐 필요한 기능을 처리하고 결과를 응답

1. 클라이언트가 API에 요청을 보냄
2. `apis`에서 요청받을 URL과 HTTP Method를 확인
3. `schemas`를 통해 요청 데이터의 형식과 타입을 확인
4. `services`에서 요청받은 기능에 필요한 로직을 처리
5. 데이터베이스 작업이 필요한 경우 `repositories`를 통해 데이터를 조회, 추가, 수정, 삭제
6. `models`에 정의된 데이터베이스 테이블 구조를 이용하여 데이터베이스와 작업
7. 처리된 결과를 API를 통해 클라이언트에게 응답

처리가 완료되면 결과는 반대 방향으로 전달되어 최종적으로 클라이엍느에게 응답

각 기능을 역할에 따라 나누면 코드가 복잡해졌을 때 수정할 위치를 찾기 쉽고 유지보수하기 편리해짐
